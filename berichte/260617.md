 Daten und Zeichenkodierung

Computer speichern alle Daten in binärer Form. Damit Zeichen für Menschen dargestellt werden können, wurde die ASCII-Tabelle entwickelt. In dieser Tabelle besitzt jedes Zeichen einen eigenen Zahlenwert.

Da ASCII nur eine begrenzte Anzahl an Zeichen unterstützt, entstanden später verschiedene Codepages. Diese unterschieden sich je nach Land und Sprache. Dadurch kam es häufig zu Problemen beim Austausch von Dateien zwischen unterschiedlichen Systemen.

Um dieses Problem zu lösen, wurde Unicode eingeführt. Unicode weist jedem Zeichen weltweit eine eindeutige Nummer zu. Die gebräuchlichste Kodierung dafür ist UTF-8. Dabei werden häufig verwendete Zeichen mit weniger Speicherplatz gespeichert als seltene Sonderzeichen.

Mit dem Befehl xxd kann man Daten in einer hexadezimalen Darstellung anzeigen.

Beispiel:

echo "a" | xxd

Dadurch wird das Zeichen „a“ als Hexwert dargestellt.

Wichtige Optionen:

* -n verhindert den automatischen Zeilenumbruch von echo
* -p zeigt nur die Hexwerte an
* -r wandelt Hexwerte wieder in normale Zeichen um

Beispiel:

echo -n "😃" | xxd -p

Ausgabe:

f09f9883

Mit folgendem Befehl kann der Wert wieder zurückgewandelt werden:

echo -n "f09f9883" | xxd -r -p

Ergebnis:

😃

Aufgabe: UTF-8 Kodierung ermitteln

Ermittelte UTF-8 Werte:

🥳 = f09fa5b3

😎 = f09f988e

👽 = f09f91bd

© = c2a9

€ = e282ac

ß = c39f

Aufgabe: Hex Dump

Mit der Option -b können sowohl xxd als auch hexdump die Ausgabe in Binärform darstellen.

Beispiel:

echo -n "A" | xxd -b

echo -n "A" | hexdump -b

Aufgabe: Bedeutung von Octet

Ein Octet besteht immer aus genau 8 Bit. Der Begriff wird verwendet, weil die Größe eines Bytes früher nicht immer eindeutig 8 Bit betrug. In der Netzwerktechnik wird deshalb oft von Octets gesprochen.

Aufgabe: Option -E

Die Option -E verwendet die EBCDIC-Zeichentabelle anstelle von ASCII. Heute wird sie nur noch selten benötigt und ist hauptsächlich für ältere Systeme relevant.

Aufgabe: Binärdaten speichern

Der Befehl

printf "%.8x" $value

wandelt eine Dezimalzahl in eine achtstellige Hexadezimalzahl um. Anschließend wird der Wert mit xxd in Binärdaten umgewandelt und in einer Datei gespeichert.

Mit folgendem Befehl kann der Wert wieder als Dezimalzahl ausgegeben werden:

echo $((16#$(xxd -p data.bin)))

Ergebnis:

65534

Aufgabe: Option -i

Mit der Option -i erzeugt xxd eine Ausgabe im Format einer C-Quelldatei. Dadurch können Binärdaten direkt in Programme eingebunden werden.

Teil 3: Windows Editor und Zeichensätze

Eine Textdatei wurde einmal als UTF-8 und einmal als ANSI gespeichert.

Bei der UTF-8 Datei wurden alle Sonderzeichen korrekt angezeigt. In der ANSI-Datei fehlten einige Zeichen oder wurden falsch dargestellt.

Daraus lässt sich schließen, dass UTF-8 die Standardkodierung der verwendeten Shell ist.

Kodierung einzelner Zeichen:

ANSI:

Ö = d6

€ = 80

ß = df

UTF-8:

Ö = c396

€ = e282ac

ß = c39f

Aufgabe: Zeilenumbrüche

Unter Linux wird ein Zeilenumbruch mit dem Bytewert 0A gespeichert.

Unter Windows werden zwei Bytes verwendet:

0D 0A

Dadurch unterscheiden sich Textdateien je nach Betriebssystem.

Aufgabe: ANSI nach UTF-8 konvertieren

Mit folgendem Befehl wurde eine ANSI-Datei in UTF-8 umgewandelt:

iconv -f CP1252 -t utf-8 Ansi.txt -o AnsitoUtf.txt

Die Konvertierung war erfolgreich und die Sonderzeichen wurden anschließend korrekt dargestellt.

Aufgabe: Unterschied zwischen ANSI und Latin-1

Latin-1 (ISO 8859-1) ist ein standardisierter Zeichensatz für westeuropäische Sprachen.

ANSI beziehungsweise Windows-1252 basiert auf Latin-1, enthält jedoch zusätzliche Sonderzeichen. Dazu gehören beispielsweise das Euro-Zeichen (€) oder spezielle Anführungszeichen.
